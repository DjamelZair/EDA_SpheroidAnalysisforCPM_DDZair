From coordinates to real estate insights

A RAG-based pipeline for structured real estate data retrieval.

Polygon coordinates of construction sites in Belgium are turned into structured, machine-readable real estate data through reverse geocoding, fallback search, context-aware re-ranking, targeted Zimmo scraping, and LLM attribute extraction. The headline result: Mistral-7B beats GPT-4 on correctness (88.9% vs 85.6%) and is 7× faster (3.6s vs 25s), and 81.6% of build sites get enriched end-to-end.

The pipeline

8 stages · 1 feedback loop
Eight-stage data flow, left to right. The dotted return path closes the loop on missing fields. Input → Geocoding → Search → Re-ranking → Scraping → RAG Extract → Enrichment → Output

How it works

Per-stage breakdown
Stage 01

Input

Polygon coordinates from KR&A: ~3,000 Belgian construction sites delineated as polygons.

Stage 02

Reverse geocoding

Polygon centroid is reverse-geocoded against OSM and a fallback provider to recover a postal address.

Stage 03

Search

Address feeds a search engine; fallback queries handle ambiguous or missing matches.

Stage 04

Re-ranking

Context-aware re-ranker scores results against the polygon context. P@2 = 0.93 over BM25.

Stage 05

Scraping

Targeted scraping on Zimmo recovers listing pages where structured fields would otherwise be missed.

Stage 06 · Highlight

RAG attribute extraction

Schema-based prompt chaining over Mistral-7B vs GPT-4. Mistral wins on both correctness and latency.

Stage 07

Enrichment

Public-amenity overlay (transport, education, healthcare) joined to the address, plus filtering rules.

Stage 08

Output

Structured records: 81.6% of polygons reach the final schema with full attribute coverage.

The result

Mistral-7B vs GPT-4

A small open model beats GPT-4 on this task.

On a sampled evaluation set of 180 listing descriptions, Mistral-7B reached 88.9% correctness on schema-based attribute extraction, against GPT-4's 85.56%. Mistral was also 7× faster, returning in 3.58s on average versus 25.02s for GPT-4 calls.

The win comes from prompt engineering plus targeted scraping: when the source page contains the field, a smaller open model with a tight schema prompt is enough.

For schema-bound real-estate extraction, the lightweight model is the right one.
